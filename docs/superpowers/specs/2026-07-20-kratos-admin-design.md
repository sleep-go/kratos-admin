# Kratos Admin 设计说明

## 目标

从空仓库交付一个原生多租户、前后端分离的通用管理后台。系统面向桌面、平板和手机，具备身份认证、组织管理、Casbin RBAC、菜单配置、数据权限、日志审计、系统设置、消息渠道和对象存储能力。

## 总体架构

仓库采用模块化单体：后端共享同一领域模型并产出 API 与 Worker 两个 Kratos 进程，前端为 Vue 3 SPA。浏览器通过 `/api/v1` HTTP/JSON 接口访问；Protobuf 是后端接口与前端类型的真相源。PolarDB MySQL 8 保存业务真相，Redis 用于权限缓存、验证码、限流和异步队列。

后端按认证、租户组织、权限菜单、日志审计、系统配置、消息渠道和文件存储分域。阻塞或可重试任务交由 Worker 处理；关键业务变更在同一事务内写 outbox，再由 Worker 幂等消费。

## 多租户与身份

用户身份全局唯一，可通过租户成员关系加入多个租户。平台管理员创建、冻结和授权租户，不开放公众注册。租户管理员只能管理当前租户。

登录支持用户名、邮箱和手机号。access JWT 默认有效 15 分钟，refresh JWT 默认有效 7 天；refresh 的 jti 哈希持久化并在刷新、切换租户时轮换。短信或邮箱 MFA 可关闭、仅管理员强制或全员强制。

所有租户业务表包含 `tenant_id`，仓储层从认证上下文取得租户，禁止普通接口信任客户端传入的租户或数据范围。

## 权限设计

平台维护目录、菜单、按钮和 API 资源，并决定租户可用功能。Casbin 使用租户 domain：成员与角色使用 `g` policy，角色与资源动作使用 `p` policy。

数据权限由查询层实施，支持全部、本部门及下级、本部门、仅本人、自定义部门。多角色取并集，但任何结果仍受租户边界限制。菜单资源只允许引用前端编译期注册的组件键。

## 日志、配置与文件

系统保存登录日志、操作审计和 API 访问/异常日志。密码、令牌、验证码、密钥和文件内容禁止进入日志。默认保留期分别为 180、365 和 30 天，平台可调整。

配置按代码安全默认、平台默认和租户允许覆盖三级解析。敏感配置加密存储，读取接口只返回是否已配置。邮件、短信和对象存储采用 Provider 接口，首版提供 SMTP、阿里云短信、本地模拟、本地文件和阿里云 OSS。

OSS 上传使用短期直传凭证，完成后由后端校验对象元数据；私有下载重新鉴权并签发短期 URL。

## 前端体验

使用顶部全局导航。默认配色为深灰渐变顶栏、红色激活态、浅灰页面背景、白色内容卡片和有限彩色功能图标。桌面显示完整导航，平板折叠，手机使用抽屉；复杂表格和权限树提供移动端适配布局。

## 明确不包含

首版不包含公开注册、OIDC、微服务拆分、应用运行日志中心、站内通知中心、Kubernetes 和深色主题。
