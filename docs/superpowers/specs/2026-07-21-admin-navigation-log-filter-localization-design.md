# 后台二级导航、日志筛选与系统设置中文化设计

## 背景

后台已经实现登录日志、操作审计、API 访问与异常日志及日志导出页面，但顶部导航将所有 `/logs/*` 路由合并为单一“日志中心”入口，并固定跳转操作审计页面，导致其他日志页面不可发现。通用资源列表目前只发送关键词，尚未将后端已支持的结构化筛选字段暴露到界面。系统设置页面直接展示后端英文分类、配置键、值类型和来源，中文体验不完整。

## 目标

- 顶部导航支持可见、可访问的二级菜单，并覆盖桌面、平板和手机布局。
- 日志仍保持三个独立页面，各页面提供与自身字段匹配的筛选条件。
- 日志异步导出复用当前列表筛选条件，确保页面结果与导出结果口径一致。
- 系统设置中的用户可见名称、分类、值类型、来源和枚举值使用中文展示；后端字段名和配置键保持不变。

## 导航设计

顶部导航的数据结构由单层项目扩展为可选 `children` 的两层结构。没有子项的导航保持现有跳转行为；存在子项时，桌面端显示下拉菜单，点击具体子项进入对应页面。日志中心包含：

- 登录日志：`/logs/login`
- 操作审计：`/logs/audit`
- API 日志：`/logs/api`
- 导出记录：`/logs/exports`

当前路由位于任一子项时，日志中心保持红色激活态。移动端抽屉将子项直接展开在“日志中心”分组下，避免依赖悬停操作。二级菜单仅基于后端实际下发且通过编译期组件注册表校验的导航项生成，不向无权限用户暴露入口。

## 日志筛选设计

通用资源定义增加声明式筛选字段，列表页面按定义渲染下拉框或输入框，并将非空值放入现有 `filters` 请求参数：

- 登录日志：登录结果、用户 ID。
- 操作审计：操作类型、资源类型、用户 ID、成员 ID。
- API 日志：HTTP 方法、状态码、用户 ID；异常筛选通过状态码或异常原因关键词完成，不新增后端字段。
- 日志导出记录：日志类型、任务状态。

查询、重置、切换日志页面时同步维护筛选状态和分页。创建导出任务时把当前筛选条件原样传入，后端继续执行字段白名单校验。

日志类型和状态值在表格中使用中文标签展示，例如 `login` 显示“登录日志”、`audit` 显示“操作审计”、`api` 显示“API 日志”；原始值仅用于接口传输。

## 系统设置中文化

前端维护稳定的展示字典，将后端标识转换为中文：

- 分类：基础资料、邮件、短信、存储、安全策略、日志保留等。
- 配置名称：根据 `category + setting_key` 映射具体中文名称。
- 值类型：字符串、整数、布尔值、时长等。
- 来源：代码默认值、平台配置、租户配置。
- 常见枚举和布尔值：启用/禁用、是/否及对应业务含义。

无法识别的新配置项采用可读化兜底：优先显示后端返回名称；没有名称时保留原始配置键，确保新增配置不会消失。编辑弹窗同时展示中文名称和只读配置键，提交载荷仍使用原始字段。

## 组件边界与数据流

- `TopNavigation`：负责桌面二级菜单的展示、激活态和交互。
- `AppShell`：将权限过滤后的导航组织为两级结构，并渲染移动端分组。
- `ResourceListView`：负责通用查询状态、筛选参数、重置和导出参数传递。
- `resourceDefinitions`：声明各资源的筛选字段、选项及表格值映射。
- 设置展示字典：集中提供分类、配置项、类型、来源的中文标签，设置面板和编辑弹窗共同复用。

后端现有列表接口、`filters` 白名单和日志导出接口已经覆盖本次字段，不修改 Protobuf、数据库结构或权限模型。

## 错误处理与兼容性

- 缺少子菜单权限时不显示该子项；整个分组没有可见子项时隐藏顶级入口。
- 筛选请求失败沿用统一 Axios 错误处理，页面保留当前条件供用户重试。
- 未知英文标识不阻断渲染，使用原始值兜底。
- 顶部无子菜单项的现有导航行为保持不变。

## 测试与验收

- 导航单元测试：日志中心生成四个授权子项、当前子路由激活、无权限子项隐藏。
- 响应式导航测试：桌面下拉与移动端展开项均可访问。
- 日志列表测试：不同页面渲染对应筛选项，请求和导出携带筛选条件，重置清空条件。
- 系统设置测试：已知分类、配置项、类型、来源显示中文，未知键安全兜底。
- 执行前端定向 Vitest、TypeScript 类型检查和 lint。

## 非目标

- 不合并三个日志页面。
- 不新增日志表、日志类型或后端查询字段。
- 不翻译底层配置键、Provider 标识或 API 传输值。
- 不调整现有顶栏配色和页面视觉主题。
