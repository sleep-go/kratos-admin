# 平台与租户权限隔离设计

## 背景

当前系统使用全局用户、租户成员关系和多租户角色模型，但全局平台管理员标记会被带入具体租户上下文。部分后端服务和前端权限指令只判断该全局标记，导致平台管理员进入租户后绕过租户角色、菜单授权和数据范围。

资源目录目前也没有明确记录菜单适用于平台域还是租户域，平台菜单依赖代码中的固定名单，新增资源时容易错误下发到租户。

## 目标

- 平台管理员只在平台上下文拥有平台治理权限。
- 租户管理员是具体租户内的成员身份，不能获得平台治理权限。
- 平台管理员进入具体租户时不得自动成为租户管理员或绕过租户权限。
- 创建租户时不创建管理员、角色或用户，也不把当前平台管理员加入租户。
- 平台管理员可在平台上下文完成租户初始化，不需要切换为租户身份。
- 菜单、操作权限和数据范围使用同一套可信上下文，平台资源与租户资源不能混淆。

## 身份与上下文

### 全局身份

`users.is_platform_admin` 只表示用户能否进入 `tenant_id = 0` 的平台上下文。该字段是全局能力，不代表用户在任何具体租户中的身份。

### 租户身份

用户进入具体租户前必须具有有效的 `tenant_members` 关系。租户内身份分为：

- 租户管理员：`tenant_members.is_tenant_admin = 1`，拥有该租户已启用功能的全部操作权限和全部数据范围。
- 普通成员：通过租户角色获得操作权限，并受角色数据范围限制。

平台管理员如果同时是某个租户的成员，进入该租户后也只按对应的租户成员身份授权。不是成员时不得进入该租户。

### 有效平台上下文

所有后端权限绕过、平台资源访问和跨租户数据访问必须同时满足：

```text
claims.platform_admin = true AND claims.tenant_id = 0
```

只判断 `claims.platform_admin` 的实现必须移除。全局平台管理员标记仍保留在登录资料中，用于展示“返回平台管理”入口，但不能直接用于租户内按钮或接口放行。

## 租户创建与初始化

### 创建租户

创建租户时只填写：

- 租户编码
- 租户名称
- 租户状态

事务只创建租户记录，不创建用户、成员、角色或管理员关系，也不自动授权租户功能。新租户允许处于没有成员和角色的初始化状态。

### 平台初始化入口

平台管理员在平台上下文通过“租户管理 → 租户初始化”选择目标租户，依次完成：

1. 配置租户可用功能。
2. 创建租户角色并配置资源动作和数据范围。
3. 创建或关联全局用户，建立租户成员关系。
4. 为成员分配角色，或将成员设为租户管理员。

初始化操作使用平台治理接口显式携带目标租户 ID。服务端只允许有效平台上下文调用，并在仓储层把写入范围固定到目标租户。平台管理员不会因此获得该租户成员身份，也不签发该租户令牌。

租户允许没有租户管理员，因此不设置“最后一位管理员不可取消”的约束。没有租户管理员时，仍可由平台初始化入口继续维护。

## 资源和菜单范围

资源目录增加适用范围字段，使用位标记表达：

- `1`：仅平台
- `2`：仅租户
- `3`：平台与租户共用

数据库字段必须包含以上完整中文 COMMENT。服务端按令牌中的上下文过滤菜单，不信任前端传入的范围。

### 平台专属资源

- 全局用户
- 租户管理
- 菜单与权限资源目录
- 租户功能授权
- 租户初始化

### 租户专属资源

- 成员管理
- 部门管理
- 岗位管理
- 租户角色
- 成员角色与租户策略

### 共用资源

- 登录日志、操作审计、API 日志和日志导出
- 系统设置与渠道配置
- 参数字典
- 文件管理

共用资源在平台上下文可以执行平台治理查询，在租户上下文必须固定为当前租户数据。菜单父节点只有在至少存在一个可见子节点时才返回或展示。

`tenant_resources` 只能关联适用范围包含租户的资源。平台专属资源即使被错误提交，也必须由后端拒绝。

## 后端授权规则

### 平台上下文

- 只允许平台管理员进入。
- 允许访问平台专属资源和适用于平台的共用资源。
- 跨租户治理操作只能通过明确的平台接口执行。
- 平台上下文的普通通用资源请求不得依赖客户端伪造租户 ID。

### 租户上下文

- 必须存在有效租户成员关系。
- 所有通用管理资源的查询、创建、更新和删除必须使用令牌中的 `tenant_id`。
- 平台管理员全局标记不得跳过 Casbin、租户功能授权或数据范围。
- 租户管理员只对该租户已授权资源拥有全部动作。
- 普通成员按角色动作和数据范围授权。

### 权限即时生效

以下变更必须递增目标租户的权限版本：

- 租户功能授权变化
- 成员角色变化
- 角色资源或数据范围变化
- 成员管理员状态变化
- 成员禁用或删除

旧访问令牌在服务端校验时因权限版本不一致而失效，前端刷新后重新加载用户权限和菜单。

## 前端行为

- 平台上下文只展示平台菜单。
- 租户上下文只展示服务端返回的租户菜单。
- 前端权限指令仅使用服务端下发的当前上下文权限，不再因为 `platformAdmin=true` 全局放行。
- 全局平台管理员标记只控制“平台管理”上下文入口是否可见。
- 平台租户初始化页面显式显示当前目标租户，避免把目标租户误认为当前登录上下文。
- 普通租户页面不得接受目标租户 ID，也不得展示平台专属资源入口。

## 兼容与数据处理

- 新创建租户不再自动产生平台管理员成员关系。
- 不自动删除已有租户成员或管理员关系，避免不可逆地移除真实权限。
- 已有平台管理员如果同时存在租户成员关系，进入租户后按该成员的管理员或角色身份授权。
- 旧资源记录通过迁移补齐适用范围；迁移对每个内置资源使用明确映射，不按名称猜测。

## 错误处理

- 非平台上下文调用租户初始化接口：返回 `PLATFORM_ADMIN_REQUIRED`。
- 平台上下文尝试把平台专属资源授权给租户：返回明确的资源范围错误。
- 用户切换到没有成员关系的租户：返回“没有可用的租户成员身份”。
- 租户成员访问平台资源：返回权限不足，不通过空列表掩盖越权调用。
- 初始化目标租户不存在、冻结或已删除：拒绝写入并保持事务回滚。

## 验证范围

### 后端测试

- 创建租户不会创建用户或成员关系。
- 平台管理员在平台上下文可执行租户初始化。
- 平台管理员在租户上下文不再绕过租户权限和数据范围。
- 租户管理员只能访问当前租户已授权资源。
- 普通成员按角色与数据范围访问。
- 平台专属资源不能写入 `tenant_resources`。
- 菜单按资源适用范围、租户功能和成员权限正确过滤。
- 权限相关变更递增权限版本。

### 前端测试

- 平台与租户上下文展示不同菜单。
- 平台管理员进入租户后，按钮不再全局放行。
- 平台租户初始化页面始终显示目标租户。
- 租户切换后重新加载当前权限和菜单。
