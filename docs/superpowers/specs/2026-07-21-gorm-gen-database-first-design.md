# GORM Gen 数据库反向生成与数据访问统一设计

## 背景

当前项目以 Goose SQL 维护数据库结构，同时在 `app/admin/internal/data/model/schema.go` 手工维护 GORM Model，再通过 GORM Gen 的 `ApplyBasic` 生成 `app/admin/internal/data/query`。这会让同一字段在迁移 SQL 和 Go Model 中重复维护，存在类型、可空性、默认值和字段遗漏等漂移风险。

数据层目前也同时使用 GORM Gen、原生 GORM `Table`、动态 SQL、`Raw` 和 `Exec`。本次改造要统一模型生成链路和运行期业务查询方式。

## 目标

1. Goose SQL 是唯一数据库结构真相源。
2. 从执行全部 Goose 迁移后的临时 MySQL 数据库反向生成 Model。
3. 基于反向生成的 Model 生成 GORM Gen Query。
4. 运行期业务 CRUD、事务和关联查询统一使用 GORM Gen。
5. 关联读取优先使用 `Preload`，需要关联过滤、聚合或投影时优先使用 `Join` 或 `LeftJoin`。
6. 生成过程可重复执行，同一提交连续生成两次不产生 Git 差异。
7. 保留 Goose 迁移的可审计性、版本管理和生产升级能力。

## 非目标

1. 不使用 GORM `AutoMigrate` 管理生产数据库结构。
2. 不从开发数据库或生产数据库直接生成代码。
3. 不在本次改造中给现有表新增数据库外键。
4. 不强制将 Goose、临时数据库管理以及 MySQL 命名锁改写成 GORM Gen。
5. 不修改前端代码或当前未提交的 `app/frontend/vite.config.ts`。

## 总体架构

生成链路如下：

```text
Goose SQL
  -> 创建唯一临时 MySQL 数据库
  -> 执行全部 Goose 迁移
  -> GenerateModel 生成 model/*.gen.go
  -> 注册显式业务关联
  -> ApplyBasic 生成 query/*.gen.go
  -> 删除临时数据库
```

Goose 继续负责数据库从版本 A 演进到版本 B。Model 和 Query 均为派生代码，禁止手工修改。

## 临时数据库生命周期

`kratos-admin-tools gorm-gen` 读取现有配置中的 MySQL DSN，但只复用服务器地址、认证信息和连接参数，不在配置指定的业务数据库中生成代码。

命令执行过程：

1. 生成不可预测且带固定前缀的临时数据库名。
2. 使用安全的标识符校验创建临时数据库。
3. 构造指向临时数据库的新 DSN。
4. 执行仓库内全部 Goose 迁移。
5. 连接临时数据库执行 Model 和 Query 生成。
6. 无论生成成功、失败或上下文取消，都尝试删除临时数据库。
7. 同时返回生成错误和清理错误，不静默丢失错误。

临时数据库不会使用生产迁移命名锁。现有迁移实现将拆分为：

- 可复用的 Goose 迁移执行函数。
- 面向真实环境、带 MySQL 命名锁的迁移入口。

创建和删除临时数据库属于生成基础设施，允许使用基础 SQL。

## Model 生成规则

反向生成范围为业务迁移创建的全部表，但排除 `goose_db_version`。

生成器维护确定性的表名、结构体名、文件名和字段类型映射：

- `BIGINT UNSIGNED` 映射为 `uint64`。
- 普通状态、类型类 `TINYINT UNSIGNED` 映射为 `uint8`。
- 明确的布尔字段映射为 `bool`。
- JSON 字段映射为 `datatypes.JSON`。
- 可空字段使用与业务语义一致的指针或 GORM nullable 类型。
- 保留数据库 COMMENT 生成的中文字段注释。
- 固定缩写命名，例如 `api_access_logs` 对应 `APIAccessLog`。

类型和命名映射集中维护并通过单元测试约束，不能散落在 Repository 中。

生成完成并验证所有现有业务引用已迁移后，删除手写 `model/schema.go`。生成目录只包含 `*.gen.go`；确需补充的非结构业务方法放在独立、非生成文件中。

## 关联关系

当前迁移没有数据库外键，GORM Gen 无法仅凭数据库结构推导完整关联关系。本次不通过新增外键改变现有数据库行为，而是在生成工具中维护显式关系元数据。

关系元数据描述：

- 关系类型：`belongs to`、`has one`、`has many` 或 `many to many`。
- 关联字段和引用字段。
- 生成到 Model 和 Query 中的关系名称。
- 逻辑删除、租户字段等关联查询约束由 Repository 显式追加。

只有真实业务查询需要的关系才进入元数据，不为了覆盖全部表提前建立无用关联。

## Query 生成

完成 Model 元数据生成后，将全部业务 Model 传给 `ApplyBasic`，继续生成默认 Query 和 Query Interface。

生成目录启用清单式清理：只删除上一次生成器记录的生成文件，不删除手写扩展文件。这样表被迁移删除或重命名后，不会遗留失效的 Model 和 Query 文件。

## Repository 统一规则

### 普通 CRUD

所有普通增删改查使用生成 DAO 和字段表达式，不再使用字符串表名或字符串字段名。

### 事务

事务统一通过生成的 `query.Query.Transaction` 执行。事务回调内只使用该事务对应的 Query，不复用事务外 DAO。

### 关联查询

1. 读取完整关联对象时优先使用 `Preload`。
2. 需要通过关联表过滤、聚合、排序或只投影部分字段时使用 `Join` 或 `LeftJoin`。
3. 避免为了消除一条 Join 而产生明显的 N+1 查询。
4. 复杂联表按具体业务评审；只有 Gen 表达明显降低可读性或无法满足数据库语义时，才考虑生成自定义查询接口。

### 行锁和 Upsert

行锁、冲突忽略和原子更新继续使用 Gen DAO 的 `Clauses`、字段赋值表达式和事务能力，不直接退回原生 `Table`。

### 通用数据管理

现有通用管理 Repository 依赖动态表名和字段名，需改造成资源注册表：

- 每个资源注册对应的生成 DAO。
- 注册允许读取、写入、排序和筛选的字段表达式。
- 注册 Model 创建器和结果转换器。
- 通用分页、过滤、排序和审计逻辑通过 `gen.Dao` 组合。

外部请求仍只允许访问注册表白名单，不允许将请求参数直接转换成数据库表名或字段表达式。

## 允许保留基础 SQL 的边界

以下内容不属于运行期业务模型查询，可以保留基础 SQL：

1. `migrations/*.sql`。
2. 创建和删除代码生成临时数据库。
3. MySQL `GET_LOCK` 和 `RELEASE_LOCK`。
4. 针对数据库迁移框架自身状态的基础设施检查。

除此之外，业务 Repository 不允许新增或保留 `.Table`、`.Raw`、`.Exec` 或直接 `database/sql` 查询。

## 错误处理和安全

1. 临时数据库名必须由程序生成并经过严格字符白名单校验，禁止直接拼接用户输入。
2. 生成命令不得对配置中的业务数据库执行迁移、清表或删除操作。
3. 生成前校验数据库服务器连接和创建数据库权限，失败时不修改已有生成文件。
4. Model 和 Query 先生成到临时目录，全部成功后再替换目标生成文件，避免生成中断留下半套代码。
5. 临时数据库清理失败必须返回错误并输出数据库名，便于人工处理。
6. Repository 迁移保持现有租户隔离、逻辑删除、权限版本、审计 Outbox、行锁和幂等语义。

## 测试与验收

### 生成器测试

- 表名、结构体名和文件名映射测试。
- 数据库字段类型映射测试。
- 临时数据库名安全校验测试。
- 排除 `goose_db_version` 测试。
- 生成清单不会删除手写文件的测试。
- 创建、迁移、生成或清理任一步骤失败时的错误传播测试。

### 数据层测试

- 现有 Repository 行为测试保持通过。
- 认证、验证码、文件、审计、任务、日志导出和通用管理的 MySQL 集成测试保持通过。
- 事务、行锁、Upsert、权限版本递增、租户隔离和逻辑删除行为不得改变。
- 新增包含 `Preload` 和 `Join` 的代表性集成测试。

### 架构约束

新增静态架构测试，扫描业务数据层并拒绝：

- `.Table(`
- `.Raw(`
- `.Exec(`
- 直接导入 `database/sql`

允许名单仅包含迁移、临时库生成基础设施和生成代码。

### 最终验收

1. 在临时数据库执行全部迁移后能完整生成 Model 和 Query。
2. 连续生成两次后 `git diff --exit-code` 通过。
3. 删除手写 Model 后项目可编译。
4. 所有目标 Repository 使用 GORM Gen。
5. Go 单元测试、MySQL 集成测试、`go vet` 和 lint 通过。
6. 生成命令失败不会破坏当前已提交的生成代码。

## 实施边界

本次改造只涉及 Go 数据模型、生成工具、Repository、测试、Makefile 和相关开发文档。现有未提交的前端修改属于用户工作，不读取其内容、不覆盖、不暂存、不提交。
